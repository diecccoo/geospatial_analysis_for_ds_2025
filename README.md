# Geospatial Analysis of Electoral Outcomes in Trento: The 2025 Ianeselli Case

Repository for the geospatial analysis and representation of electoral outcomes in Trento, developed for the 2025 University of Trento data science course.

## Repository Layout

### data
This folder contains the datasets used by the project and the generated outputs.

#### data/raw
These are the original source files.

- districts.geojson: polygons of the municipal districts used to aggregate and summarize the analysis.
- R04_21_WGS84.shp, R04_21_WGS84.dbf, R04_21_WGS84.prj, R04_21_WGS84.shx: the ISTAT census-block shapefile, split into its standard components. The shapefile is the spatial base used to reconstruct the electoral sections and to attach demographic indicators.
- sections.geojson: civic-point geometries with section identifiers and address-related attributes. This is the main point layer used to rebuild the electoral sections and to connect addresses with the map.
- sezioni_elettorali.shp, sezioni_elettorali.dbf, sezioni_elettorali.prj, sezioni_elettorali.shx, sezioni_elettorali.cpg: the official electoral-section shapefile, stored in the usual shapefile components.
- stops_urbano.txt: stop list for the urban public-transport network, including stop name and coordinates.
- stops_extraurbano.txt: stop list for the extraurban public-transport network.
- Voti_Sindaco.csv: mayoral vote results by section, used to compute the Ianeselli vote share.

#### data/processed
This folder stores intermediate and final outputs generated by the Python workflow.

- trento_elections.geojson: processed analytical dataset at section level. It combines vote share, demographic indicators, density, and transport-accessibility measures.
- trento_electoral_map.html: the interactive Folium map generated by the script in scripts/trento_electoral_map.py.

The interactive map is the main output of the project. It is built from the processed section layer and combines several thematic layers: districts, ISTAT census blocks, standard electoral sections, special electoral sections, civic points, public-transport stops, and bypass construction sites. The map uses a diverging color scale centered on 50 percent for the Ianeselli vote share, so the visual balance between stronger and weaker support is easy to read.

The workflow behind the map is the following. First, the Python pipeline reconstructs the electoral sections from the civic points by buffering the points and dissolving them by section identifier. Then it merges the election results and the socio-demographic indicators stored in data/processed/trento_elections.geojson. For each section it keeps, among others, the vote share, the percentage of highly educated residents, the percentage of non-EU residents, density, and average distance to the nearest transit stop. The HTML map then renders these values through choropleth-style polygons, popups, labels, clustered transit stops, and a search box for civic addresses only.

Two UX details are worth noting. Special electoral sections are treated as a separate layer and also have dedicated civic points shown in grey, so they can be inspected without being mixed with the standard sections. The search control is focused on civic addresses, and when a result is found the matching feature is highlighted and its popup is opened automatically. A reset control restores the default view and clears the highlight.

### r_scripts
This folder contains the R workflow used for exploratory and statistical analysis.

- 00_data_exploration.R: initial inspection of the data, descriptive summaries, thematic maps, and correlation-style visual checks.
- 01_global_autocorelation.R: global spatial autocorrelation analysis, including Moran-type diagnostics and supporting maps.
- 02_local_analysis.R: local spatial analysis and cluster-oriented interpretation of the patterns in the data.
- 03_spatial_regression_models.R: spatial regression models and tabular reporting of the results.
- r_plots/spatial_regression_table.tex: LaTeX output with regression-table formatting.

### scripts
This folder contains the Python scripts that build the processed dataset and the interactive map.

- build_trento_elections.py: builds the section-level analytical dataset in data/processed/trento_elections.geojson. It reconstructs sections from civic points, merges the vote counts, computes vote share and demographic indicators, and estimates accessibility to transit stops.
- trento_electoral_map.py: builds the interactive HTML map in data/processed/trento_electoral_map.html. It loads the processed data, prepares the layers, and adds the map controls, popups, search box, and clustered transit-stop layer.

## Requirements

The Python dependencies needed to run the project are listed in requirements.txt. They cover the Python scripts and the other Python-based pieces of the repository.

For the R workflow in r_scripts/, install the packages used there separately in your R environment. The main ones are sf, dplyr, ggplot2, tmap, ggcorrplot, tidyr, ggpubr, spdep, spatialreg, and texreg.

## How to run the Python workflow

1. Install the Python requirements.
2. Run scripts/build_trento_elections.py to generate data/processed/trento_elections.geojson.
3. Run scripts/trento_electoral_map.py to generate data/processed/trento_electoral_map.html.

## Notes on the data files

The raw shapefiles are stored in split form, so every dataset that appears as a .shp also depends on its companion .dbf, .prj, .shx, and, when present, .cpg file. Keep each group together when moving or copying the repository.
